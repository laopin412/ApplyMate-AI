# ApplyMate AI — UI/UX 設計規格 v1

## 1. 視覺方向（已確認）

採 **D：專業與科技混合風**，以白色／深藍為主，科技藍和局部藍紫漸層點綴；不用過量的發光、玻璃擬態或複雜特效。

建議設計色碼（先前視覺示意，仍可於 UI 實作時微調）：

| 色彩角色 | 示意色碼 |
|---|---|
| 背景白 | `#FFFFFF` |
| 主深藍 | `#172B4D` |
| 科技藍 | `#4C83D5` |
| 藍紫點綴 | `#8875D8` |

版面原則：乾淨留白、清楚層級、可辨識操作狀態、柔和陰影與適度圓角；色彩對比與可鍵盤操作仍需於實作檢核。

## 2. 響應式（已確認）

**電腦與手機同等重要**：不是把桌機畫面等比縮小。桌機、平板、手機都需設計合理的選單、表單、卡片與檢視方式。具體斷點尚未選定。

## 3. 公開首頁（五個區塊，已確認）

```text
┌──────────────────────────────────────────────┐
│ Logo   功能介紹   使用流程   登入   開始使用   │
├──────────────────────────────────────────────┤
│ HERO：標題／價值主張／開始使用／視覺區         │
├──────────────────────────────────────────────┤
│ 核心功能介紹                                 │
├──────────────────────────────────────────────┤
│ 使用流程介紹                                 │
├──────────────────────────────────────────────┤
│ FOOTER                                       │
└──────────────────────────────────────────────┘
```

- 選單僅 Logo、功能介紹、使用流程、登入、開始使用（暫不加 FAQ 等新入口）。
- 功能介紹／使用流程可用頁內跳轉；Logo 回到公開首頁。
- 點「開始使用」不先跳註冊頁：未登入者進訪客儀表板，已登入者進會員儀表板。
- 手機公開首頁導覽改漢堡選單。

## 4. 平台 Layout（已確認）

- **左側主選單＋頂部工具列**。
- 側邊欄六項：儀表板、個人資料、學校申請管理、備審文件、AI 模擬面試、系統設定。
- 頂部：通知鈴鐺、使用者／訪客身分、帳號相關操作。
- 手機：側邊欄收合成可展開選單；長表格改卡片或支援水平捲動／切換檢視。

## 5. 綜合型儀表板（已確認）

1. 上：申請學校、文件狀況、面試、錄取等統計。
2. 中：近期重要日期與待辦事項。
3. 下：學校申請摘要、備審文件狀況與快速功能入口。
4. 首次使用：歡迎訊息＋可略過的**新手任務清單**。

新手清單四項：建立個人基本資料、新增申請學校、整理學歷／專題、生成第一份備審文件；系統根據實際資料判斷完成，不強迫排序或填寫。

## 6. 個人資料頁（已確認）

```text
[個人資料管理] [完成度] [手動新增] [AI 文件匯入]
┌────────────────┬───────────────────────────┐
│ 九大分類選單    │ 選中類別的多筆資料／表單   │
│ 基本資料        │ 草稿自動保存提示           │
│ 學歷背景        │ [取消修改] [儲存資料]       │
│ ...             │                           │
└────────────────┴───────────────────────────┘
```

- 手機以分類選擇器代替內側欄；表單欄位按手機寬度單欄顯示。
- 完成度只依五項必要欄位；另外顯示各類經歷筆數，不把缺乏證照／競賽呈現為負面評價。
- 自動草稿狀態需明確區分「草稿已保存」與「正式資料已更新」。

## 7. AI 文件匯入（已確認）

- 上傳 PDF／DOCX／TXT → AI 擷取 → 九類分類預覽 → 勾選／修正 → 與既有資料比較 → 使用者確認匯入。
- 預設不寫入未確認欄位；對重複資料提供可辨識提示；衝突並列新舊內容。
- 「原始文件對照」可作為延伸功能，尚未正式定案。

## 8. 學校申請管理頁（已確認）

- 上方統計卡；中間提醒；下方學校卡片／表格切換。
- 每筆申請可進入詳細頁：學校、科系、組別、重要日期、目前狀態、備註、歷程。
- 申請狀態由使用者自己改；統計與提醒跟著已保存的資料更新。
- 數據、學校與日期的展示範例只能標示「示意」，不得當作真實使用者資料。

## 9. 備審文件頁（規劃中）

- 可進入「學校客製化」或「通用文件」流程，**首版先處理客製化**。
- 若背景不足，先顯示缺漏提示並讓使用者選擇補充或直接生成。
- 預覽 AI 生成草稿，後續需有編輯和保存機制；詳細編輯器與匯出 UI 未確認。

## 10. 體驗提醒

- 訪客應看到資料只在目前瀏覽器保存的明確提示。
- 未驗證會員應看到驗證 Email 後才能啟用雲端保存的狀態提示。
- 通知中心應能區分已讀／未讀與事件已過期；是否需要額外分類與篩選待定。
